# Long-episode protocol (Go / isolated worker)

Keep version 1 and existing endpoints/headers. POST /internal/podcast/transcribe receives a streamed full source file (Content-Length required), never a URL. Worker performs internal sequential <=600-second recognition chunks and returns the existing {"version":1,"segments":[{"start":0,"end":1,"text":"..."}]} envelope only after all chunks succeed. Timestamps are absolute episode seconds and ordered/nonoverlapping. Never truncate at a chunk boundary or fabricate speech/progress.

Hard ceilings: 300 MiB encoded source, 10800 seconds (3h), 3600 segments, 216000 source Unicode characters, 8000 characters per segment; response <=4 MiB. Defaults use these maxima. PODCAST_MAX_BYTES and PODCAST_MAX_DURATION_SECONDS may only lower their respective hard ceilings (invalid values must fail closed). Go remote request timeout 90 minutes; total durable processing budget 120 minutes; lease 125 minutes. Worker must finish recognition within 90 minutes (prefer its existing stage/process supervision with a total recognition deadline).

Worker must stream upload to bounded disk workspace, decode/recognize one <=600-second chunk at a time, remove each decoded chunk/output before the next, and remove source/workspace on completion/failure/cancellation. No full decoded episode in RAM or tmpfs. The implemented worker uses a 512 MiB noexec tmpfs for the encoded source and bounded JSON only, charged within its 2 GiB no-swap cgroup. Continuous PCM is piped, never saved in full. This measured bounded design supersedes the initial dedicated-disk proposal; preserve existing UID/capability/network/read-only protections.

Go checkpoints the complete transcript and each completed translation batch. Retries/recovery resume untranslated batches without refetching or recognizing when a transcript checkpoint exists. Recognition progress within a single HTTP request is NOT checkpointed: interruption there restarts recognition. This limitation must be documented honestly. Translation batches use stable episode segment IDs and strict JSON schema/mapping, preserving original timestamps. Existing personal-owner translation quotas remain unchanged; batches, not individual Whisper segments, consume attempts.
