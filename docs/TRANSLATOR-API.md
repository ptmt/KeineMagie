# Translator API contract (native + web)

Native clients use the existing Apple application session `Authorization: Bearer <app-session>`, never an OpenAI key. Browsers use the distinct Secure HttpOnly cookie session obtained by explicit iOS approval, with exact Origin + memory-only `X-CSRF-Token` for mutations; see [WEB.md](WEB.md). No Apple web Services ID is required for app-approved pairing. All responses are no-store. JSON errors `{ "error": "bounded message" }`.

- `GET /v1/provider`: `{ "connected": false, "status": "not_connected|setup_required|connected|reauthorization_required", "message": "..." }`. Connected responses also include `models: [{slug,display_name}]` and `selected_model` (prefer `gpt-6-luna` only when actually offered; otherwise first visible model). Catalog is obtained for this user's actual grant.
- If credentials are stored and accessible but catalog discovery fails, status is `catalog_unavailable`, `connected:true`, `models:[]`, `selected_model:""`. This confirms stored connection, **not** working model access; clients show the bounded server warning and disable translation until a model is offered. Catalog authorization/network failures never echo upstream bodies.
- `POST /v1/provider/connect` (empty JSON object): `{ "bootstrap_token": "single-use secret", "expires_in": 300, "message": "..." }`. Requires configured server encryption key. User runs the KeineMagie local bootstrap on a desktop, enters server URL and this short-lived code via stdin. Bootstrap opens official ChatGPT consent and runs an HTTP 127.0.0.1 listener; **do not navigate a remote/mobile browser to a made-up server OAuth callback**. Show label `Continue with ChatGPT`, a copyable code and setup instructions. Do not persist code to browser storage.
- `POST /v1/provider/disconnect`: 204 local disconnect; attempts discovery-based remote refresh-session revocation, clears only this user's tokens and retains encrypted registration/subject mapping. `X-Revocation-Status: unconfirmed` requires a warning to disconnect in ChatGPT Settings too.
- `POST /v1/translations`: `{text,source_language:"de|ru",target_language:"ru|de"}`. 201 returns existing translation record `{id,created_at,text,source_language,target_language,translation,idioms:[],patterns:[],vocabulary:[]}`. Minimal fast translation first, enrichment intentionally empty. Server streams upstream Responses internally and returns only completed result; failed/partial streams are never saved. No paid fallback.
  - The upstream request explicitly uses Responses `text.format` with a strict JSON schema `{ "text": string }`. Only after `response.completed`, the server validates and decodes exactly this one envelope, then saves/returns its `text` value as `translation`. Native and web require no parsing changes. Literal JSON, code fences, whitespace, Unicode and multiline formatting **inside** the translation are preserved, never recursively unwrapped. Plain output that violates the requested schema, empty/malformed/mixed results, extra/duplicate fields and refusals fail with generic 502 and are not saved. A completed output snapshot can supply text when no deltas were emitted; when both are present they must agree.
  - Existing history is not rewritten or heuristically unwrapped on read: a stored JSON-looking string could be legitimate translated content. Any historical repair requires explicit owner review, a backup and a separately authorized targeted migration; retranslating the affected entry is the safe non-destructive alternative.
- `GET /v1/translations`: `{items:[...]}` newest first, this Apple user only; works without provider connected. Unowned legacy history is never exposed to account sessions.

401 means invalid/expired application session; 400 invalid request; 429 bounded rate/concurrency/daily quota (also fail-closed quota storage/configuration error); 503 connection/setup/reauthorization required; 502 upstream/catalog/stream failed. Text limit 8000 characters; JSON 64 KiB; upstream `max_output_tokens:8192`; completed text limit 64 KiB. One active translation per user (cross-process file lock). `TRANSLATION_DAILY_ATTEMPTS` defaults to 100 per UTC day (1–10000); attempts, including failures, are persisted before upstream work and survive restart. No paid fallback. TTS remains unavailable for ChatGPT sessions: subscription scope does not establish audio permission.

Bootstrap-only endpoints (not a browser OAuth redirect): `POST /v1/provider/bootstrap/start` with `{bootstrap_token,redirect_uri}` returns `{authorize_url}`; `POST /v1/provider/bootstrap/complete` with `{bootstrap_token,callback_url}` returns 204. Single-use, five minutes, tied to initiating Apple session/user. Credentials are exchanged server-side and never returned to either client. Local bootstrap is `cd server && go run . connect`; prompts for server URL and bootstrap token. Only explicit localhost development HTTP and HTTPS server origins accepted.
